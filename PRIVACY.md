# Privacy

Sona has no account, telemetry endpoint or transcript history service. Microphone audio is captured only for an active dictation. Mac uses Apple's on-device Speech framework; Windows uses local Whisper. Speech assets and runtime dependencies require an initial network download.

Sona holds raw recordings, dictation results, selected text and unsaved suggestions in memory. An ordinary dictation result that cannot be inserted safely remains in memory for explicit copying. Sona does not write those contents to transcript files, request files or local provider sessions. The operating system may page process memory or include it in a crash dump; this is not a guarantee of secure memory erasure. The receiving app, clipboard managers and a remote AI provider can retain their own copies.

Optional AI cleanup sends transcript text, after local saved-phrase expansion, and configured vocabulary to the selected provider. Dictation and snippet setup make at most one economy request. CLI routes reuse supported authentication but start isolated requests without prior provider session context, project instructions, execution tools, hooks or configured MCP servers. They disable local session persistence. Sona refuses the reviewed Gemini CLI route because it cannot meet that last condition. Sona does not inspect, copy or delete preexisting CLI history. API cleanup routes use a named environment variable and a single tool-free request. Remote provider retention, billing, organization policies and account limits still apply.

Select provider None to disable all AI requests. Turning cleanup off disables the ordinary dictation AI pass; separately invoked snippet suggestions can still use the configured provider. Saved phrases expand locally and require no AI call. Failed ordinary cleanup returns the exact raw local recognition result.

The second hotkey and Assistant have been removed. Sona does not capture your screen, run screen conversations or request Screen Recording permission. Any previously granted screen permission is unused. Old Assistant and second-shortcut preferences are ignored, with no change to the saved dictation shortcut, sound or provider. Files generated by much older versions remain in the user's Creations directory until the user removes them.

Snippet setup runs only when explicitly requested. It sends only the setup details you supply, such as a scheduling link or signature, to your configured provider. It does not search past chats, browse files, use connected services or relax provider isolation. There is no launch task, timer or background setup request. Every proposed trigger and expansion is shown for review. Only entries you confirm and save become part of your private config. Empty or failed suggestions lead to manual editing.

Sona monitors its single configured dictation shortcut while running. It does not keep a keyboard history. Nonmodifier shortcut capture requires keyboard events to identify that chosen key. Ordinary text events are not logged. Accessibility/UI automation identifies the focused destination so Sona can refuse insertion after a focus change.

During a Mac dictation session, a compatibility guard also observes mouse-down and key-down events in other applications and application activation changes. It retains a session identifier and activity revision, not typed characters, key identities, or mouse positions. The configured finish key is compared only inside the callback. This allows an editor with unavailable or coarse Accessibility data to receive a paste only while its PID, available window identity, and session activity remain unchanged. Known protected fields are refused. An inaccessible field's identity and protection status cannot be fully determined, so this fallback is weaker than exact field matching. The guard uses existing Accessibility access.

Corrected-spelling suggestions are **off by default**. While off, Sona creates no correction observers, timers or helper workers and makes no extra text reads for this feature. Normal hotkey and safe-insertion checks remain active.

When enabled, the correction window lasts at most **15 seconds from a verified Sona insertion**. Activity never extends it. Observation is confined to the range Sona inserted in the same field; it is not a general keyboard recorder or whole-document scan. It stops when the window expires, the feature is disabled, focus changes, another recording starts, an edit crosses the owned range, or ownership becomes uncertain. Sona does not read a stale fixed range after deletion, which could include neighboring text. Independent typing outside the range is not eligible for observation or learning.

Both platforms require a verified insertion into an otherwise empty, supported plain-text field. They do not observe mixed documents with preexisting text or read neighboring text as an anchor. Windows uses supported UI Automation text ranges and a bounded helper process for native reads. Only a witnessed edit within the inserted span can authorize another content read; unknown or out-of-range changes stop observation first. If a field cannot provide the necessary range and edit guarantees, Sona skips correction observation while ordinary dictation remains available. This is not universal support across applications. No additional system permission is introduced beyond the app's existing Accessibility/UI Automation access.

On Mac, correction suggestions support insertions of at most 4096 UTF-8 bytes and wait 800 milliseconds after a verified edit for the spelling to settle. An enabled correction window temporarily registers an event tap restricted to the destination application's process. It checks field identity, character count and selection position before forwarding input unchanged. It reads text only after a matching Accessibility edit notification confirms a witnessed edit. A failed or timed-out check ends observation. On Windows, correction suggestions currently support single-line ASCII insertions of at most 4096 characters and selecting a whole word to replace with alphabetic keys. A 500-millisecond pause lets the spelling settle. Neither settling period extends the 15-second deadline.

Only a confidently identified corrected word is offered for addition to vocabulary, and it requires confirmation. The offer and its source text stay in memory until accepted or dismissed. There is no model request for correction detection and no silent config write. An accepted vocabulary spelling is saved as a setting, not as transcript history.

Automatic insertion temporarily uses the clipboard. Sona restores its prior contents only if the clipboard has not been changed by another action. Clipboard managers and the receiving app can retain inserted text independently. Explicit Copy recovery leaves the result on the clipboard intentionally.

Private configuration lives in the user's home/profile directory, outside the repository. It includes vocabulary, saved phrase triggers and expansions, the dictation hotkey and the correction-observation switch. Vocabulary and phrase editors save reviewed drafts. The retired Assistant choices are removed on the next successful settings save. Diagnostic logs contain status, counts and generic failure categories, not transcript, selected text, setup context or credential text. No personal developer configuration, AI credentials or recording media is distributed in this repository.
